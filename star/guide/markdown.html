Markdown 渲染 ​

AI 回复内容中的 Markdown 通过 Web Worker 离线渲染，不阻塞主线程 UI。

为什么用 Web Worker ​

AI 返回的长文本 Markdown 解析（特别是包含大量代码高亮和数学公式时）在主流设备上耗时 50-200ms。在主线程执行会导致页面卡顿、打字延迟、滚动掉帧。

Worker 线程独立于主线程，即使解析耗时也不影响用户打字、滚动等交互。

技术架构 ​

主线程 (UI)                    Worker 线程
    │                              │
    │  new Worker('./worker.js',   │
    │    { type: 'module' })       │
    │ ──────────────────────────▶ │  初始化 markdown-it
    │                              │  注册 highlight.js
    │                              │  注册 KaTeX 插件
    │                              │
    │  postMessage(markdown_raw)   │
    │ ──────────────────────────▶ │  md.render(markdown)
    │                              │  ├─ 代码块 → hljs 高亮
    │                              │  ├─ 数学公式 → KaTeX
    │                              │  └─ 生成操作按钮HTML
    │                              │
    │  ◀────────────────────────── │
    │  postMessage(rendered_html)   │
    │                              │
    ▼                              │
  v-html 渲染到 DOM

Worker 实现 ​

js
// worker.js
import MarkdownIt from 'markdown-it'
import mdKatex from '@traptitech/markdown-it-katex'
import hljs from 'highlight.js'
import vue from 'highlight.js/lib/languages/xml'
import react from 'highlight.js/lib/languages/xml'
import xml from 'highlight.js/lib/languages/xml'

hljs.registerLanguage('vue', vue)
hljs.registerLanguage('react', react)
hljs.registerLanguage('xml', xml)

// 生成带操作按钮的代码块 HTML
const highlightBlock = (str, lang, word) => {
  const codeIndex = Date.now() + Math.floor(Math.random() * 10000000)
  // Base64 编码代码内容（处理特殊字符）
  const encodedCode = btoa(
    new TextEncoder().encode(word)
      .reduce((data, byte) => data + String.fromCharCode(byte), '')
  )
  return `
    <pre class="pre-code-box">
      <div class="pre-code-header">
        <span class="code-block-header__lang">${lang}</span>
        <div class="code-block-header__actions">
          <span class="code-block-header__copy"
                data-clipboard-action="copy"
                data-clipboard-target="#copy${codeIndex}">
            📋 复制代码
          </span>
          <span class="code-block-header__download"
                data-code="${encodedCode}"
                data-lang="${lang}">
            ⬇️ 下载代码
          </span>
        </div>
      </div>
      <div class="pre-code">
        <code class="hljs code-block-body ${lang}">${str}</code>
      </div>
    </pre>
    <textarea style="position:absolute;top:-9999px;left:-9999px;z-index:-9999;"
              id="copy${codeIndex}">${word}</textarea>
  `
}

const mdi = new MarkdownIt({
  linkify: true,
  highlight(code, language) {
    const validLang = !!(language && hljs.getLanguage(language))
    if (validLang) {
      const lang = language ?? ''
      return highlightBlock(
        hljs.highlightAuto(code, [lang]).value,
        lang,
        code
      )
    }
    return highlightBlock(hljs.highlightAuto(code).value, '', code)
  }
})

mdi.use(mdKatex, {
  blockClass: 'katexmath-block rounded-md p-[10px]',
  errorColor: '#cc0000'
})

self.onmessage = function(e) {
  if (!e.data) {
    self.postMessage('')
    return
  }
  const result = mdi.render(e.data)
  self.postMessage(result)
}

主线程调用 — 消息队列模式 ​

采用懒加载 + Promise 消息队列模式，防止流式数据的并发覆盖：

ts
// Worker 懒加载 + 消息队列
let _worker: Worker | null = null
const _pendingQueue: Array<(value: string) => void> = []

const getWorker = (): Worker => {
  if (!_worker) {
    _worker = new Worker(new URL('./worker.js', import.meta.url), {
      type: 'module',  // 支持 ES Module
    })
    _worker.onmessage = e => {
      const resolve = _pendingQueue.shift()
      if (resolve) resolve(e.data)
    }
  }
  return _worker
}

// 消息队列模式 — 返回 Promise，保证回调顺序
const renderInWorker = (content: string): Promise<string> => {
  return new Promise(resolve => {
    const w = getWorker()
    _pendingQueue.push(resolve)
    w.postMessage(content)
  })
}

// 使用示例（SSE onmessage 回调中）
renderInWorker(markdownContent).then(html => {
  msg.adminContent.adminText = html
})

为什么用消息队列 ​

SSE 推送的 token 速度很快（每 50-100ms 一个），而 Worker 渲染是异步的。如果直接用 onmessage 回调，后发的内容可能先生成，导致渲染错乱。

消息队列模式将每次 postMessage 包装为 Promise，按入队顺序依次 resolve，确保渲染结果与发送顺序一致。

代码块操作 ​

Worker 渲染的代码块自带两个操作按钮：

复制代码 ​

使用 Clipboard.js 实现一键复制。通过事件代理在聊天容器上统一处理：

ts
// onMounted
chatContainer.value?.addEventListener('click', (e) => {
  const target = (e.target as HTMLElement).closest('[data-code]')
  if (target) {
    const encodedCode = target.getAttribute('data-code') || ''
    const lang = target.getAttribute('data-lang') || ''
    downloadCode(encodedCode, lang)
  }
})

下载代码 ​

Base64 解码 → Blob → URL → 触发浏览器下载：

ts
const downloadCode = (encodedCode: string, language: string) => {
  // 解码 Base64
  const binaryString = atob(encodedCode)
  const bytes = new Uint8Array(binaryString.length)
  for (let i = 0; i < binaryString.length; i++) {
    bytes[i] = binaryString.charCodeAt(i)
  }
  const code = new TextDecoder().decode(bytes)

  // 确定文件扩展名
  let ext = language
  if (language === 'javascript') ext = 'js'
  else if (language === 'typescript') ext = 'ts'

  // 触发下载
  const blob = new Blob([code], { type: 'text/plain' })
  const url = URL.createObjectURL(blob)
  const a = document.createElement('a')
  a.href = url
  a.download = `code.${ext}`
  a.click()
  URL.revokeObjectURL(url)
}

性能要点 ​

策略说明
Worker 懒加载首次渲染时才创建 Worker 实例，避免首屏初始化开销
消息队列Promise + 数组队列，保证流式数据的渲染顺序
独立线程Worker 解析不与主线程竞争 CPU 时间片
事件代理代码块复制/下载使用容器级事件代理，不绑定单个元素
Base64 编码代码内容通过 TextEncoder → Base64，安全传递特殊字符
